# 듣기 음원 만들기 가이드 (Gemini TTS · 1회성 작업)

> 이 작업은 **개발 단계에서 딱 한 번**만 하면 됩니다. 만들어진 음원은 영구 보관되고,
> 서비스 운영 중에는 TTS를 다시 호출하지 않습니다(운영비 0원 원칙).
> 실제 스크립트 실행은 준비물만 갖춰지면 Claude Code가 대신 해드릴 수 있습니다 —
> **아래 1단계(API 키)만 직접 주시면 됩니다.**

## 왜 Google Cloud TTS가 아니라 Gemini API인가

Google Cloud Text-to-Speech는 **GCP 결제 계정**이 필요한데, 계정당 "결제를 켤 수 있는
프로젝트 수" 한도(보통 5개)에 걸려 새 프로젝트에 붙이지 못하는 상황이 있었습니다.
**Gemini API 키는 이미 발급받아 쓰고 있어** 추가 절차가 전혀 없으므로 그쪽으로 갑니다.

| | Google Cloud TTS | **Gemini TTS (채택)** |
|---|---|---|
| 준비 | GCP 결제 계정·프로젝트 필요 | **기존 키 그대로** |
| 발음(미·영·호) | 전용 보이스 ID로 고정 | 프롬프트 지시문으로 지정 |
| 대화(L3·L4) | 줄마다 따로 합성 후 이어붙임 | **멀티 스피커로 한 번에** 합성 |
| 출력 | MP3 | PCM → WAV(ffmpeg 있으면 MP3) |

⚠️ 발음이 보이스 ID로 고정되지 않으므로, **미·영·호 구분이 실제로 들리는지 생성 후 확인**이
필요합니다(아래 3단계). 구분이 약하면 상용 출시 전에 Cloud TTS로 갈아탑니다 —
스크립트에서 합성 함수만 바꾸면 되도록 분리해 두었습니다.

## 1단계 — Gemini API 키 (직접, 이미 있으면 건너뛰기)

이미 쓰고 계신 Gemini API 키를 그대로 쓰면 됩니다. 새로 받아야 한다면:

1. [Google AI Studio](https://aistudio.google.com/app/apikey) 접속 → 구글 계정 로그인
2. **"Create API key"** 클릭 → `AIza...` 로 시작하는 문자열 복사
3. 키는 비밀번호처럼 다뤄 주세요. 유출되면 같은 화면에서 삭제하면 즉시 무효화됩니다.

> 참고: TTS 모델은 **유료 등급에서 안정적으로 동작**합니다. 무료 등급은 분당 요청 수가
> 매우 낮아 중간에 429(할당량 초과)가 자주 납니다. 스크립트가 자동 재시도하지만
> 오래 걸리므로, 유료 등급 키를 쓰거나 `TTS_DELAY`를 크게 잡아 주세요.

## 2단계 — 음원 생성 (Claude가 실행)

```
node tools/import.mjs                              # 문항 ID 매핑 생성
GEMINI_API_KEY=<키> TTS_LIMIT=3 node tools/tts-batch.mjs   # 먼저 3개만 시험 생성
GEMINI_API_KEY=<키> node tools/tts-batch.mjs               # 문제없으면 전량 생성
```

- 산출물: `tools/out/audio/` 폴더의 음원 + `audio-manifest.json`
- 대화(L3·L4)는 멀티 스피커로 한 번에, L2는 질문+보기 4개를 한 트랙으로 만듭니다.
- 이미 만든 파일은 건너뛰므로, 중간에 끊겨도 **다시 실행하면 이어서** 만듭니다.

**조절 가능한 옵션** (환경변수)

| 변수 | 기본값 | 용도 |
|---|---|---|
| `TTS_MODEL` | `gemini-2.5-flash-preview-tts` | 고품질이 필요하면 `gemini-2.5-pro-preview-tts` |
| `TTS_DELAY` | `1500` | 요청 간격(ms). 429가 잦으면 3000 이상으로 |
| `TTS_LIMIT` | 없음 | 앞에서 N개만 만들고 중단 (시험용) |

**용량 주의**: ffmpeg가 없으면 WAV로 저장되어 파일이 약 15배 큽니다.
`apt install ffmpeg` (또는 맥: `brew install ffmpeg`) 후 실행하면 자동으로 MP3(64kbps)로
변환합니다. 이미 만든 WAV는 지우고 다시 실행하면 MP3로 다시 만듭니다.

## 3단계 — 청취 검수 (사용자 확인 필요)

전량 생성 후 **표본 청취**로 아래를 확인합니다. 특히 발음 구분은 이번 방식의 핵심 리스크입니다.

- [ ] **미국·영국·호주 발음이 서로 구분되게 들리는가** (파트별로 3개씩 들어보기)
- [ ] 속도가 초등 저학년이 따라올 만한가 (앱에서 0.9배속도 지원)
- [ ] L2에서 질문과 보기 A~D 사이 간격이 충분한가
- [ ] L3 대화에서 두 화자의 목소리가 확실히 구분되는가
- [ ] 스크립트에 없는 말(안내 문구 등)이 섞여 들어가지 않았는가

## 4단계 — R2 업로드·연결 (Claude가 실행)

1. Cloudflare R2 버킷 `jumplish-assets` 생성 → 음원 업로드
2. 버킷에 공개 도메인 연결 (Cloudflare 대시보드에서 R2 → 버킷 → Settings → Public access)
3. `R2_PUBLIC_BASE=<공개 주소> node tools/import.mjs` → seed 재적용 → 앱에서 음원 재생 확인

## 자주 묻는 것

- **왜 실시간으로 안 만들고 미리 만드나요?** 학생이 들을 때마다 TTS를 호출하면 비용이 계속 나갑니다.
  미리 만들어 두면 몇 만 명이 들어도 추가 비용이 0원입니다.
- **비용은?** 시드 120문항은 합성 글자수가 수만 자 수준이라 한 번 만드는 데 몇 천 원 안쪽입니다.
  실제 금액은 첫 시험 생성(`TTS_LIMIT=3`) 후 AI Studio 사용량 화면에서 확인하세요.
- **키가 유출되면?** AI Studio 키 목록에서 삭제하면 즉시 무효화됩니다.
