# AI 숏폼 동화 스튜디오

주제 한 줄로 한국 전래동화 쇼츠(9:16)를 반자동 제작한다. 휴대폰만으로 조작한다.

```
관리자 페이지에서 주제 입력
  → GitHub Actions가 대본 + 씬별 영상 프롬프트 생성
  → (프롬프트를 복사해 Runway·Pika 등에서 씬 영상 제작)
  → 관리자 페이지에서 씬 영상 업로드
  → GitHub Actions가 나레이션 + 가라오케 자막 입혀 최종 MP4
  → 관리자 페이지에서 바로 재생·다운로드
```

무료다. 화면은 Cloudflare Workers, 무거운 영상 작업은 GitHub Actions, 파일 보관은
GitHub Release가 맡는다. 저장소의 `book-carousel`·`verdict-theater`와 같은 구조다.

## 구조

```
shorts_studio/
├── admin/                  관리자 페이지 (Cloudflare Workers)
│   ├── public/index.html   모바일 UI — 표지·인물기준이미지·프롬프트복사·영상업로드·재생
│   ├── worker/index.mjs    로그인·GitHub 호출·업로드 중계·완성본 재생
│   ├── build_users.py      아이디별 시크릿 → 사용자 목록
│   └── put_secrets.sh      워커에 비밀값 밀어 넣기 (배포·주기반영이 공유)
├── core/                   제작 엔진 (Actions와 로컬이 공유)
│   ├── llm.py              줄거리 → 씬 대본 + 툴별 영문 프롬프트 (Gemini)
│   ├── tts.py              Gemini TTS 합성 + 줄 단위 실측 타이밍
│   ├── subtitle.py         가라오케 ASS 자막
│   └── video.py            FFmpeg 규격변환·합성·자막번인
├── content/<id>.json       작품 기록 (대본·상태·완성본 주소) — Actions가 커밋
├── run_script.py           ① 주제 → 대본
├── run_render.py           ② 영상 + 대본 → 최종 MP4
└── app.py                  (선택) 로컬 PC에서 쓰는 Streamlit 단독 실행판
```

워크플로: `.github/workflows/shorts-studio-script.yml` · `shorts-studio-render.yml` ·
`deploy-shorts-studio-admin.yml` · `shorts-studio-sync-secrets.yml`

**⭐ 비밀번호를 바꾸면 최대 15분 안에 저절로 반영된다.**
GitHub 시크릿을 고쳐도 그것만으로는 워커에 전달되지 않는다 — 누군가 밀어 넣어 줘야 한다.
예전엔 사람이 배포를 다시 돌려야 했고, 그걸 모르면 "비밀번호를 바꿨는데 안 들어가진다"가 된다.
그래서 `shorts-studio-sync-secrets` 가 **15분마다 알아서 밀어 넣는다.** 당장 반영하려면
[그 워크플로](https://github.com/jtaechul/Product/actions/workflows/shorts-studio-sync-secrets.yml)
에서 **Run workflow** 를 누르면 된다. 배포 워크플로와 **같은 `put_secrets.sh`** 를 쓴다 —
두 군데에 같은 코드를 두면 한쪽만 고쳐져 같은 사고가 또 난다.

## 처음 한 번만 하는 준비

| 이름 | 쓰임 |
|---|---|
| `GEMINI_API_KEY` | 대본·성우의 **기본** 키 (쓰는 사람이 자기 키를 넣으면 그게 우선) |
| `CF_API_TOKEN` | 관리자 페이지 배포 |
| `CLOUDFLARE_ACCOUNT_ID` | 어느 Cloudflare 계정에 올릴지 |
| `MOVIEGEN_ADMIN_PASSWORD` | 1인 모드 비밀번호 (아이디는 `admin`) |
| `MOVIEGEN_ADMIN_GH_TOKEN` | 워커가 쓸 GitHub 토큰 (Contents·Actions 모두 Read and write) |
| `MOVIEGEN_USER_1`~`_8` | (선택) 여러 사람이 쓸 때 — **아이디 하나에 시크릿 하나** |
| `MOVIEGEN_SESSION_SECRET` | (선택) 로그인 위조 방지용 |
| `MOVIEGEN_KEY_SECRET` | (선택) 개인 API 키를 봉할 열쇠 |

사용자는 **아이디마다 시크릿을 하나씩** 만든다. 값은 한 줄:

```
MOVIEGEN_USER_1  →  jt:내비밀번호:장태철
MOVIEGEN_USER_2  →  mina:다른비밀번호:미나
```

`아이디:비밀번호:보여줄이름`. 이름은 빼도 되고(아이디를 쓴다), 비밀번호에 콜론이 있어도 된다
(마지막 콜론 뒤가 이름). 여기 없는 사람은 못 들어오고, 칸을 지우면 그 즉시 로그아웃된다.

**왜 한 칸에 몰아 두지 않는가**: GitHub 시크릿은 **한 번 넣으면 다시 볼 수 없다.** 전부 한 칸에
두면 세 번째 사람을 넣을 때 앞의 두 명 것까지 다시 타이핑해야 하고, 하나라도 빠뜨리면 그 사람이
조용히 로그인 못 하게 된다. 칸을 나눠 두면 **추가는 빈 번호에 새로 하나, 수정은 그 칸 하나**로
끝나고 나머지는 손댈 일이 없다. 배포할 때 `admin/build_users.py` 가 칸들을 모아 워커에 넣는다.
(옛 방식 `MOVIEGEN_USERS` — JSON 한 줄 — 도 칸이 하나도 없을 때만 계속 받아 준다.)

혼자 쓸 때는 **아이디 칸을 비우고 비밀번호만** 치면 된다(아이디는 여러 명일 때만 필요).

**⭐ 관리자 계정(`admin` + `MOVIEGEN_ADMIN_PASSWORD`)은 언제나 살아 있다.**
예전엔 `USERS` 가 있으면 `ADMIN_PASSWORD` 를 통째로 무시했다. 그래서 사용자 칸을 하나
등록하는 순간 관리자 비밀번호가 죽었고, 그걸 아무리 바꿔도 안 들어가졌다(실제로 겪었다).
지금은 사용자 목록에 **더해서** 항상 관리자 계정을 얹는다 — 목록을 잘못 넣어도 주인은 잠기지 않는다. GitHub 토큰은 워커 안에만 있다.

## 설계 메모

**아이디마다 제 작품만 보인다.** 대본 기록에 `owner` 를 박고, 목록·업로드·렌더가 모두 주인을
확인한다. 남의 작품은 목록에 뜨지도, 영상을 덮어쓰지도 못한다.

**⭐ 개인 API 키는 봉해서 보낸다 — 이 저장소가 공개라서.**
실제 작업은 GitHub Actions 에서 돈다. 그런데 워크플로 입력값은 **실행 기록 화면에 그대로
보인다.** 공개 저장소이므로 사용자의 API 키를 날것으로 넘기면 전 세계에 공개된다.
그래서 이렇게 한다: 키는 **쓰는 사람의 폰(브라우저)에만** 저장하고, 작업을 보낼 때만 워커로
넘긴다 → 워커가 AES-GCM 으로 잠가(`sealKey`) 워크플로 입력에 넣는다 → 같은 열쇠
(`KEY_SECRET`)를 가진 Actions 만 연다(`core/seal.py`). 기록에는 알아볼 수 없는 문자열만 남고,
푼 키는 `::add-mask::` 로 로그에서도 가려진다.
한계: 열쇠가 새면 지난 기록의 암호문을 풀 수 있다. 열쇠를 바꾸면 그 순간부터 무효가 된다.

**대본은 네 단계로 만든다.** ① 줄거리와 인물(발단·전개·위기·절정·결말) → ② 컷마다 무슨 일이
벌어지는지 한 줄씩 → ③ 그 개요를 여덟 개씩 묶어 본문 작성 → ④ **전체 나레이션을 한 화면에 놓고 윤문**.
한 번에 다 시키면 모델이 앞뒤를 안 보고 컷을 지어내어 이야기가 끊기고, 컷이 많을수록
뒤쪽이 통째로 부실해진다.

**④ 윤문이 필요한 이유 — 실제로 나온 대본을 재 보고 넣었다.**
컷을 여덟 개씩 나눠 쓰면 묶음 경계에서 말맛이 끊긴다. 흥부놀부 10컷을 뽑아 보니
① 종결어미가 무작위로 섞이고(답니다/어요/뭐예요/지요) 이웃한 컷이 같은 말로 끝나고
② 32~45자 규칙을 절반이 어겨 최대 55자(한 문장에 사건 셋)가 나오고
③ 인물 이름을 매 컷 되불러(흥부 5번·놀부 5번) 낭독체가 딱딱해지고
④ 1번이 "옛날 옛적에"로 시작해 훅이 아니었다.
이건 컷 하나만 봐서는 안 보이고 **전체를 한 화면에 놓아야** 잡힌다. 그래서 마지막에
나레이션만 모아 말맛을 다듬는 호출을 한 번 더 한다. 사건·순서·인물은 건드리지 못하게
막고, 결과가 개수가 안 맞거나 길이가 이상하면 **그 줄만 원본으로 되돌린다** — 다듬다가
대본을 잃는 일은 없다. 다듬은 뒤에도 남은 어색함(길이 초과·어미 중복·이름 반복)은
`_check_flow` 가 경고로 알려 준다.

**개요 단계에서 단계를 건너뛰지 못하게 막는다.** 흥부놀부에서 "놀부가 못된 꾀를
마음먹었다" 바로 다음이 "놀부의 박이 열렸다"였다 — 제비 다리를 부러뜨리고, 박씨를 받고,
심는 세 단계가 통째로 빠져 보는 사람이 "박씨를 어디서 났지?" 하게 된다. 그래서 개요를
다 쓴 뒤 이웃한 두 컷을 짚으며 "앞 컷이 끝난 상태에서 이 컷이 바로 시작될 수 있는가"를
스스로 묻고, 빠진 일이 있으면 그것도 컷으로 넣게 했다.
컷 수에 따라 대목마다 몇 컷씩 줄지 미리 나누므로(`allocate_acts`), 20컷이면 전개가 여섯 컷으로
두꺼워지지 컷만 잘게 쪼개지지 않는다.

**⭐ 운율과 자막 싱크를 동시에 잡는 법 — 조각 하나 = 자막 한 줄.**
나레이션은 Gemini TTS로 만든다. 그런데 Gemini TTS는 "몇 초에 어떤 말을 했는지"를 안 알려준다.
그래서 예전엔 **20자마다 끊어 따로 합성**했다 — 자막은 정확했지만, 조각마다 제 나름의 억양으로
시작하고 끝맺어 **문장의 흐름이 사라졌다**("평면적이고 기계적"의 진짜 원인).

지금은 **절(clause) 단위로 끊는다.** 문장 끝과 쉼표에서 자르고, 그 조각을 **그대로 자막 한 줄**로
쓴다. 그러면 두 가지가 한꺼번에 해결된다.
- **운율**: 성우가 완결된 구를 통째로 읽으므로 억양 곡선이 산다.
- **싱크**: 줄 경계 = 조각 경계 = **측정값**. 추정할 일이 없다. 자막이 어긋날 수가 없다.

줄 **안**의 어절 하이라이트만 보간한다. 조각 안의 실제 공백 수가 어절 사이 수와 정확히
맞으면 그대로 쓰고(사실상 실측), 아니면 음절 수 비례로 나눈다.
(검증: 줄 경계 오차 0ms · 어절 오차 중앙 9ms / 최악 77ms. 어절을 거의 붙여 읽는 최악의 경우에만
비례로 떨어져 중앙 150ms.)

⚠️ 어절마다 닻을 박으려던 시도는 **실패했다.** 말 빠르기가 흔들리면 비례 어림이 누적으로 밀리고,
그 상태에서 공백을 고르면 **한 칸씩 밀린 짝짓기가 더 싸 보여** 자막이 통째로 밀린다(1.3초까지
어긋났다). 정답은 더 똑똑한 정렬 알고리즘이 아니라 **줄 경계를 추정하지 않아도 되게 구조를
바꾸는 것**이었다.

**⭐ 페르소나는 고정, 연기만 씬마다 다르게.** 예전엔 조각마다 지시문을 조금씩 바꿨는데
(첫 줄이냐, 문장 중간이냐…) Gemini 는 지시문이 바뀌면 **목소리 톤까지 같이 바뀐다.**
그래서 씬마다 목소리가 흔들렸다. 지금은 `build_style()` 이 **영상 내내 글자 하나 다르지 않은**
페르소나([목소리]·[상황]·[규칙])에 씬별 `voice_direction` 만 얹는다.

**연기 마커는 대본 안에 직접 넣는다.** Gemini 는 SSML 을 안 받지만 `[속삭이며]` 같은 **대괄호
인라인 지시**는 알아듣는다. 대본 AI가 감정이 꺾이는 자리에 씬당 1~2개를 박아 넣고,
합성할 때는 그대로 보내되 **자막에서는 걷어낸다**(`strip_markers`) — 안 그러면 화면에
"[슬픔]" 이 그대로 뜬다. 무료 성우(Edge)로 넘어갈 때도 반드시 걷어낸다. Edge 는 마커를
못 알아듣고 **소리 내어 읽어버린다**.

**이음새는 제로크로싱 + 페이드로 잇는다.** 조각을 딱 잘라 붙이면 파형이 수직으로 튀어
'툭' 소리가 난다. 앞뒤를 **파형이 0을 지나는 지점**으로 옮기고 10ms 페이드를 건다 — 길이가
안 바뀌므로 자막이 밀리지 않는다. 말 중간을 억지로 끊은 자리(쉼 0)에서만 20ms 크로스페이드를
쓰고, **겹친 만큼 시작 시각을 당겨** 타임라인을 보정한다.
pydub 은 쓰지 않는다 — mp3 프레임 여백 때문에 조각마다 수십 ms씩 늘어나 자막이 밀린다.

**나레이션은 씬별로 따로 만든다.** 씬 영상 길이를 그 씬의 나레이션 길이에 정확히 맞추기
위해서다. 전체를 한 덩어리로 만들면 말과 화면이 뒤로 갈수록 밀린다.

**⭐ 인물 일관성 — 이 프로젝트에서 가장 중요한 설계.**
씬마다 영상 AI가 따로 그리면 주인공이 컷마다 다른 사람이 된다. 유일하게 확실한 해법은
**인물마다 기준 이미지 한 장**을 만들어 그 인물이 나오는 모든 씬에 함께 넣는 것이다
(image-to-video). 등장인물은 최대 3명까지 만들고(많을수록 운영자가 만들 이미지가 늘어난다),
씬마다 `cast` 로 누가 나오는지 적어 두어 어떤 이미지를 넣어야 하는지 화면에 보여 준다.
목록에 없는 사람은 뒷모습·실루엣·먼 군중으로만 나온다.
그래서 외모는 각 인물의 `image_prompt` 에서만 정하고, **씬 프롬프트에는 외모를 한 글자도
쓰지 않는다** — 참조 이미지와 글이 싸우면 이긴 쪽이 컷마다 달라져 옷이 계속 바뀐다.
`strip_look_words()` 가 씬 프롬프트에 외모 낱말이 새어 들어갔는지 검사해 경고한다.
(`verdict-theater/CLAUDE.md` 의 "루미나 3대 금지" 중 ①을 이식)

**인물은 말하지 않는다.** 나레이터가 들려주는 이야기라 인물이 입을 움직이면 누가 말하는지
헷갈리고, 영상 AI가 지어낸 영어 입모양은 한국어 나레이션과도 어긋난다. LLM 이 매번 쓰기를
기대하지 않고 `SILENCE_LOCK` 한 문장을 **모든 씬 프롬프트에 예외 없이 붙인다**.
발화 동작(shouts·sings 등)이 씬 내용에 섞이면 `talk_words()` 가 경고한다.

**씬 전환은 나레이션 여백 안에서 일어난다.** 각 씬 영상을 제 길이보다 전환 시간만큼 길게
만들어 두고, `xfade` 가 그 여분을 정확히 먹는다. 이 계산이 틀어지면 뒤로 갈수록 말과 그림이
밀리므로, k번째 전환은 앞선 씬 길이의 합에서 시작하고 마지막에 남는 한 번분만 잘라낸다.
전환 효과는 순서대로 돌려 써서 같은 효과가 반복되지 않게 한다.

**⭐ 워터마크는 위아래 검은 띠로 덮는다.** 영상 생성 AI가 화면 구석에 제 이름을 박아 넣는다.
`finalize` 가 화면 위아래에 검은 띠를 그린 **뒤** 자막을 올리므로 자막은 가려지지 않는다.
**아래 띠가 위보다 두껍다(기본 위 8% · 아래 16%).** 워터마크는 오른쪽 아래에만 박히기
때문이다. 실제 결과물을 재 보니 1280 높이 영상에서 워터마크가 바닥에서 103~145px 지점에
있었다 — 8%(102px)로는 그 **바로 아래까지만** 덮여 하나도 안 가려졌다. 16%(205px)면 60px
여유를 두고 덮인다. 자막은 아래 띠보다 위에 놓아 글자가 띠에 걸치지 않게 한다.
관리자 페이지에서 "워터마크 가림"으로 조절한다.
띠 픽셀 수는 파이썬에서 정수로 못 박는다 — ffmpeg 식(`ih*0.08`)에 맡기면 소수점이 잘려
맨 아랫줄 한두 픽셀이 새고, 거기로 워터마크 끄트머리가 비친다(실제로 겪었다).

**표지에서 제목을 읽어 준다.**
표지가 머무는 시간은 **제목 낭독 길이에 맞춰 정해진다**(앞 0.35초 + 낭독 + 뒤 0.65초,
최소 1.8초). 고정 시간으로 두면 제목이 잘리거나 어색하게 남는다. 제목은 씬과 **같은
성우·같은 페르소나**로 읽어야 표지에서 본문으로 넘어갈 때 목소리가 안 바뀐다.
할당량이 바닥나 무료 성우로 갈아탈 때도 제목까지 함께 다시 뽑는다.

**표지는 맨 앞.** 대본을 만들 때 표지 이미지 프롬프트(`cover_prompt`)를 함께 뽑는다.
그림에는 **글자를 넣지 않는다** — 영상·이미지 AI가 쓰는 한글은 반드시 깨지므로, 제목은
시스템이 ASS 자막으로 또렷하게 얹는다. 제목은 화면 **위쪽**에 두어 인물 얼굴을 가리지 않는다.
표지를 올리면 뒤따르는 모든 자막이 표지 길이만큼 밀리고, 그만큼 무음이 나레이션 앞에 깔린다.
표지를 안 올리면 그냥 건너뛴다.

**같은 주소에 새 파일을 올리면 캐시를 반드시 깨야 한다.** 인물 이미지를 바꿔 올려도 릴리스
자산 주소는 그대로라, 워커가 캐시를 허용하면 폰이 **옛 그림을 계속 보여 준다**(실제로 겪었다).
그래서 ① 워커가 이미지에 `no-store` 를 붙이고 ② 자산 번호를 주소 뒤에 달아(`?v=<id>`)
올릴 때마다 다른 주소가 되게 한다. 다시 렌더한 완성본도 `rendered_at` 을 달아 같게 처리한다.

**업로드와 재생은 워커가 중계한다.** 브라우저에서 깃허브 업로드 서버로 바로 쏘면
CORS 에 막히고(실제로 "연결이 끊겼습니다" 로 나타났다), 릴리스 주소는 `attachment` 로
내려와 사파리가 인라인 재생을 거부한다(검은 화면). 워커가 둘 다 풀어 준다.

## 알려진 제약

| 항목 | 내용 |
|---|---|
| 워크플로 위치 | GitHub 규칙상 `workflow_dispatch`는 **기본 브랜치(main)에 있는 워크플로만** 실행된다. |
| **Gemini 성우 할당량** | 자막 한 줄이 곧 호출 한 번이다. 10컷이면 20번쯤 부르는데, **무료 등급은 이걸 못 버틴다**(실제로 10컷 렌더가 429로 죽었다). 그래서 할당량이 바닥나면 **무료 성우(Edge)로 자동으로 갈아타 끝까지 만든다** — 감정 연기는 빠지지만 빈손으로 끝나지 않는다. 감정 연기를 계속 쓰려면 **결제된 개인 API 키**를 관리자 페이지에 넣어야 한다. |
| Edge-TTS 차단 | 예비 엔진(`engine=edge`). 일부 데이터센터 IP에서 마이크로소프트가 403을 낼 수 있다. |
| 인물 일관성 | 기준 이미지를 영상 툴의 **참조 이미지** 칸에 매번 넣어야 효과가 있다. 안 넣으면 컷마다 인물이 달라진다. 한 씬에 두 명이 나오면 두 장을 같이 넣는다(툴이 지원해야 한다). |
| 업로드 용량 | 무료 Cloudflare 는 한 번에 100MB 까지 받는다. |
| 표지·인물 이미지 | 사람이 직접 만들어 올린다. 표지는 선택(안 올리면 건너뜀), 인물은 안 올리면 컷마다 얼굴이 달라진다. |
| 컷 수와 손품 | 최대 20컷. 컷 하나에 영상 클립 하나를 **사람이 직접 만들어 올려야** 한다. 20컷이면 클립 20개다. 코드가 아니라 이게 실제 한계다. |
