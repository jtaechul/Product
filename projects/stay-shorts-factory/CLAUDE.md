# 숙소 쇼핑쇼츠 팩토리 — Claude Code 프로젝트 규칙

> 숙소(쿠팡 트래블)를 소개하는 30초 세로 영상을 자동으로 만들고, 운영자가 1탭 승인하면
> 인스타 릴스 + 유튜브 쇼츠에 발행해 쿠팡 파트너스 수수료를 얻는 파이프라인.
> 원본 계획서와 결정 기록: claude.ai 프로젝트 "오토 캐쉬 카우" 문서 `claude/stay-shorts-plan.md`.
> 폴더 이름 `stay-shorts-factory` 는 작업용 이름이다 (채널 이름 미정).
> 위치: `main` 브랜치의 `projects/stay-shorts-factory/` (2026-10-09 main 반영). 작업 브랜치는
> `claude/stay-shorts-factory` 와 `claude/stay-shorts-video-conversion-67hiin` (Veo 방식). 영상 1편 만들기:
> `requests/produce/request.json` 의 `stay`(숙소 이름)·`nonce` 를 바꾸고 `"mode": "veo"` 를 두고 푸시
> → `stay-shorts-produce` 워크플로 → Release `stay-run-N` 에 `video.mp4` + `compare_sheet.jpg`, 텔레그램에도 전달.

## 핵심 규칙 — 키·시크릿은 요청하기 전에 반드시 먼저 확인한다

- 운영자에게 키 등록을 요청하기 전에 **아래 표와 워크플로 실행 결과로 등록 여부를 먼저 확인**한다.
  이미 있는 키를 다시 등록하라고 하지 않는다 (중복 등록 사고가 실제로 반복됐다).
- 새 이름의 시크릿을 만들지 않는다. 아래 이름을 그대로 쓴다.
- 이 세션의 GitHub 연결은 시크릿 목록 조회가 막혀 있다. 확인은 `stay-shorts-probe` 워크플로
  (이름만 출력)나 운영자 화면으로 한다.

| 시크릿 이름 | 용도 | 상태 |
|---|---|---|
| `COUPANG_ACCESS_KEY` / `COUPANG_SECRET_KEY` | 쿠팡 파트너스 Open API | 등록됨 (2026-10-09 운영자 화면 확인) |
| `GEMINI_API_KEY` | 대본·음성(TTS)·사진 분류(비전)·Veo 영상 | 등록됨. **Veo 유료 호출 성공 확인 (2026-10-09 stay-run-4)** |
| `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` | 완료·실패 알림 | 다른 워크플로가 사용 중. 이 워크플로에서도 전송 성공(HTTP 200) |
| `PEXELS_API_KEY` / `PIXABAY_API_KEY` | 무료 실사 영상·사진 | 다른 워크플로가 사용 중 |
| `IG_ACCESS_TOKEN` | 인스타 발행 | 다른 계정용. 새 계정은 새 토큰 필요 (계정 만든 뒤) |
| `SHORTS_YT_*`, `YOUTUBE_*` | 유튜브 업로드 | 다른 채널용. 새 채널은 새 인증 필요 (채널 만든 뒤) |

선택 변수(저장소 Variables, 없으면 코드 기본값): `STAY_VEO_MODEL`(기본 `veo-3.1-lite-generate-preview`),
`STAY_RUN_KRW`(한 번 실행 한도, 기본 3,000원), `STAY_MONTH_KRW`(한 달 한도, 기본 50,000원).

## 운영자가 원하는 영상 방식 (2026-10-09 운영자 제시 · 확정 · 구현됨)

- 2026-10-09 첫 시험본(사진 확대 + 자막, stay-run-3)은 운영자 평가 "허접하다, 내가 생각한 방식이 아니다" → 폐기.
  코드는 `mode` 없이 실행하면 아직 돌지만 비교용일 뿐이다.
- 운영자가 참고로 준 수동 제작법과 자동화 대응:
  1. 숙소 사진 **7장** — 물놀이 공간 3장, 객실 내부(침대 등) 2장, 특별한 공간(산책로 등) 2장
     - 원래는 홈페이지·예약 사이트 캡처. 2026-10-09 엔 스크래핑·저작권 규칙 때문에 **쿠팡 API 사진(객실당 1장, 숙소 이름 검색 시 10장)**
       + **운영자가 `requests/produce/photos/` 에 넣은 사진**(있으면 우선)만 썼다 → **2026-10-11 운영자 결정으로 숙소 공식 홈페이지
       사진 수집(`src/crawl_photos.py`)을 추가** — 우선순위: 운영자 폴더 → 공식 홈페이지 → 쿠팡 (아래 '공식 홈페이지 사진 수집' 섹션)
     - 분류는 **Gemini 비전**이 사진을 보고 한다 (물놀이/객실/특별/제외). 모자라는 분류는 가까운 분류에서 채운다
       (물놀이 부족 → 특별 → 객실 순). 4장 미만이면 제작하지 않는다. `src/photos.py`
  2. 사진마다 **Veo 이미지→영상 4초** — 사진에 맞는 짧은 영문 지시문("드론 글라이드 + 물결" 등)을 Gemini 가 사진을 보고 쓰고,
     코드가 항상 "사진에 없는 것 추가 금지·글자 금지" 문장을 뒤에 붙인다. `src/veo.py` (verdict-theater 이식)
  3. 7컷을 이어 붙이고 숙소명·고지문(항상) + 줄별 자막(시간대별) + 나레이션(TTS). `src/make_stay.py::produce_veo`
- 핵심은 정지 사진이 아니라 **드론 샷·물결 같은 실제 움직임이 있는 고퀄리티 컷**
- 1:1 사진 → 9:16: Gemini 가 준 초점(focus_x/y)이 가운데 오게 **실제 사진 부분만 세로로 잘라낸다**(좌우 약 44% 잘림).
  블러 배경이나 Veo 가 위아래를 상상해 채우는 방식은 쓰지 않는다 (과장 광고 규칙)
- 승인 자료: 컷마다 원본(크롭) 사진과 Veo 첫 장면을 나란히 둔 `data/runs/latest/compare_N.jpg` 와 한 장짜리
  `compare_sheet.jpg` (Release·텔레그램에도 첨부). 실제와 다른 시설·전망이 보이면 폐기

## Veo 방식 시험 결과 (2026-10-09 실측 · stay-run-4 · 히든클리프 호텔 제주)

- **성공.** 제작 단계 4분 54초(분류·대본·음성 + Veo 6회 호출), 28.96초 영상. 텔레그램 영상·비교시트 전송 HTTP 200
- **비용**: 컷당 4초 = **294원**(720p $0.05/초 · 환율 1,470). 7컷 전부면 2,058원. 이번엔 6회 호출 1,764원(장부 `state/spend.json`)
  - 단가 출처: 공개 가격표 Veo 3.1 Lite 720p $0.05/초 · 1080p $0.08/초 (verdict-theater 의 $0.08 은 1080p 값)
  - 장부는 **요청이 받아들여진 순간** 적는다(보수적). 구글이 생성 실패분을 청구하지 않으면 장부가 실제보다 많이 나온다 → 청구서로 한 번 대조할 것
- **클립 5/7**: 2컷이 구글 쪽 일시 오류로 빠졌다
  - 컷 2: 생성 중 `code 13 internal server issue` (요청 수락 후 실패)
  - 컷 3: 요청 단계 `HTTP 429 You exceeded your current quota` — **분당 호출 한도**. 바로 다음 컷은 통과했다
  - 대응(구현됨, 미실측): 429 는 60초, code 13 은 20초 쉬고 최대 2번 다시 한다. 안전필터·돈 한도는 재시도하지 않는다
- **컷이 빠지면 끝이 정지 화면**이 됐다(20초 영상 + 28초 나레이션 → 끝 9초 정지). 대응(구현됨): 영상 전체를 최대 1.5배까지
  느리게 늘린 뒤 모자라는 만큼만 정지. 재시도가 되면 7/7 이 정상이라 거의 안 쓰일 것
- **사진 구성의 한계**: 이 호텔의 쿠팡 사진 10장은 물놀이 7·객실 1·외관 1·글자 배너 2(제외). 객실 1장·특별 공간 1장을 수영장 사진으로
  채웠다 → 영상이 수영장 위주. **객실·산책로 사진은 운영자 폴더로 보완해야 운영자 구성(3·2·2)이 나온다**
- **정확성**: Veo 첫 장면은 원본과 같다(이미지→영상 특성). 중간 장면의 왜곡은 눈으로 검수. Gemini 가 글자 배너 사진과 사람 있는 사진을 잘 가려냈다
- Veo Lite 4초 컷의 움직임은 **잔잔한 편**(정지 프레임으로 보면 차이가 작다). 더 큰 움직임이 필요하면 지시문의 카메라 이동 폭을 키운다
- 실측 규격: `predictLongRunning` + `instances[0].image{bytesBase64Encoded,mimeType}` + `parameters{aspectRatio 9:16, durationSeconds 4, resolution 720p, personGeneration ALLOW_ALL, seed}` 통과.
  모델 이름은 `veo-3.1-lite-generate-preview` (verdict-theater 와 같음). Gemini 비전 분류는 `gemini-3.8-flash` 가 처리

## 벤치마크 — 운영자가 준 참고 영상 (2026-10-11 분석 · "강릉 호텔 스카이베이 VS 세인트존스 비교해볼까?")

- 규격: 57초 · 720x1280 · 60fps · 22샷(평균 2.6초, 1.5~3초가 대부분) · 나레이션 + 배경음 연속
- **포맷 = 두 숙소 비교(VS)**: 훅 "A VS B 비교해볼까?" → A 장점·**단점**("객실이 작고 답답함", "뷰 빼고는 아쉬움") → 시설 이용료 숫자("8월 성수기 기준 성인 4만원") →
  B 는 더 좋은 점("풀 1개 더", "사우나 포함", "체크아웃 전까지 이용 = 개꿀") → 객실 뷰 → 조식(모르면 "비교 어렵다"고 솔직히) → 반려견 객실(타깃 상황) → **결론은 맨 끝**("두 곳 중 하나를 추천드리면")
- 영상: 드론 외관 + 손으로 찍은 객실 POV + 풀에 들어간 사람(본인) + 노을·슬라이드·실내 돔풀. 사람이 있어 진짜 후기로 읽힌다
- 자막: **한 줄, 화면 위 1/3, 흰 글씨+검정 테두리, 1~2초마다 교체, 나레이션과 동기**. 훅만 3색(노랑 "강릉 호텔" / 흰 박스 "A VS B" / 초록 "비교해볼까?")
- 말투: 1인칭 솔직 후기 + 가벼운 유행어("럭키비키", "개꿀") + 조건·꿀팁 + 기준일 표기
- 우리가 가져갈 것: ① VS 포맷(순위표의 1·2위 또는 같은 테마 두 곳) ② 단점 한 개를 반드시 말한다(블로그 후기에서 자주 나오는 아쉬움을 API 스니펫으로 집계) ③ 자막 스타일·템포 그대로 ④ 결론 유보 ⑤ 숫자는 시설 이용료처럼 확인 가능한 것만, 기준일과 함께 ⑥ 타깃 상황 한 줄(반려견·아이)

- 한계·주의: ① 사진에 사람·글자가 있으면 Gemini 분류가 걸러내지만 완벽하지 않다(미리보기 시트로 눈 검수) ② 호텔 사진의 상업적 사용 허락은 받지
  않았다(운영자 결정: 묵인 전제, 요청 시 삭제) ③ 숙소 하나당 렌더 10페이지 ≈ 1~2분 — 제작 시간이 3곳에 5분쯤 늘어난다

## 지켜야 할 규칙

- **공식 홈페이지 외에는** 스크래핑하지 않는다. 쿠팡·네이버·인스타·OTA(야놀자·아고다 등)는 절대 금지(약관·파트너스 계정 정지).
  숙소 공식 홈페이지는 사진·시설 사실 수집에 한해 허용(2026-10-11 운영자 결정 · `src/crawl_photos.py` 의 규칙: robots.txt 준수·차단 시 포기·출처 장부).
  그 외 소재는 쿠팡 공식 API, 공공누리 1유형(한국관광공사 TourAPI 등), 운영자가 직접 준 자료만 쓴다.
- 제휴 고지문 `이 포스팅은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다`
  를 설명·캡션 첫 줄과 댓글에 넣는다. 빠지면 발행을 중단한다.
- AI 영상은 실제 사진을 시작 프레임으로 쓴다. 실제와 다른 객실·전망·시설이 나오면 폐기한다
  (과장 광고). 승인 화면에서 원본 사진과 나란히 보여 준다 (`compare_sheet.jpg`).
- 자기 제휴 링크를 프로그램이 따라가지 않는다 (부정 클릭).
- 키 값·서명은 로그와 파일에 쓰지 않는다. 저장소가 공개다.
- 운영자는 코드를 모른다. 조작은 관리자 화면 버튼으로 제공하고, 설명은 쉬운 말로 한다.
- 모든 실행은 GitHub Actions. 완성 영상(mp4)은 커밋하지 않고 Release 로 올린다.
- 유료 생성(Veo)은 `src/veo.py` 한 곳에서만 부르고, 한 번 실행·한 달 한도를 **돈 쓰기 전에** 본다. 한도는 운영자가 말할 때만 올린다.
- 저장소 공통: 한 커밋은 한 프로젝트 폴더만 수정한다 (`.github/` 만 예외).

## 쿠팡 API 점검 결과 (2026-10-09 실측 — `data/probe/result.json`)

- 키: `COUPANG_ACCESS_KEY` / `COUPANG_SECRET_KEY` 로 호출 성공. `SHORTS_COUPANG_*` 는 없다 (중복 없음)
- 경로: 검색·베스트는 `/v2/providers/affiliate_open_api/apis/openapi/products/...` (v1 없음),
  제휴링크는 `.../openapi/v1/deeplink`
- **숙소는 검색 API 로 나온다.** "가평 풀빌라"·"제주 호텔" 검색 → 각 10건, 카테고리 `Travel`,
  제휴 링크가 바로 붙어서 온다 (링크 종류 `AFFTDP`). 제휴링크를 따로 만들 필요가 없다
- **한계 1 — 상품명이 '객실 이름'이다** ("스탠다드 트윈", "A1" 등). 숙소 이름·지역이 응답에 없다
  → 숙소 이름을 얻는 방법이 필요하다 (검색어를 숙소 이름으로 하거나, 다른 합법 출처와 결합)
- 사진은 상품(객실)당 1장 (`productImage`) — 숙소 이름으로 검색하면 객실 여러 개가 와서 해결된다 (아래)
- 카테고리 베스트 1025(국내여행)·1026(해외여행)은 여행 책·지도가 나온다. 숙소 발굴에는 못 쓴다
- 제휴링크 변환: 트래블 홈(`https://trip.coupang.com/`)은 변환된다. 임의로 넣은 상품·목록 주소는
  실패했다 (주소가 틀렸을 수 있어 결론 아님)
- 응답 안내문: 게시글에 "파트너스 활동을 통해 일정액의 수수료를 제공받을 수 있음" 기재 필수

## 숙소 이름 검색 + 첫 시험 제작 결과 (2026-10-09 실측)

- **숙소 이름으로 검색하면 그 숙소의 객실이 나온다.** "히든클리프 호텔 제주"·"롯데리조트 속초"·
  "소노캄 여수" → 각 10건, 사진 10장이 서로 다르고 크기는 1000x1000 이다. 사진 부족 문제는 풀렸다

- 검색 `limit` 상한은 10 이다 (20 은 "limit is out of range")
- 첫 시험(stay-run-3, 사진 확대 방식)은 성공했지만 운영자 평가로 폐기 → Veo 방식으로 전환 (위)
- 이 키로는 `gemini-2.5-flash` 가 404 다 (신규 사용자 종료). 모델은 목록을 받아 새 것부터 차례로
  시도한다 — 실제 사용: 글·비전 `gemini-3.8-flash`, 음성 `gemini-3.8-flash-tts`. 모델 이름을 고정하지 말 것
- GitHub 러너에 ffmpeg 가 기본으로 없다 → 워크플로가 설치한다
- 워크플로에 `toJSON(secrets)` (전체 시크릿 읽기)를 넣으면 실행이 `action_required` 로 보류된다
  → 넣지 않는다. 시크릿은 이름을 지정해서만 쓴다
- 이 세션에서 실행 결과를 보는 법: GitHub MCP `actions_list`/`get_job_logs` 또는 공개 API
  `https://api.github.com/repos/jtaechul/Product/actions/runs/<id>`. 결과 파일은 워크플로가 브랜치에
  커밋 → `git pull` 로 읽는다. 미리보기·비교 사진은 `data/runs/latest/`, 완성 영상은 Release `stay-run-N`

- 호텔 공식 홈페이지 사진을 영상에 쓰는 것은 **허락을 받지 않은 상태**다 (2026-10-11 운영자 결정으로 진행). 호텔·플랫폼의 저작권 신고가
  오면 해당 영상을 내리고 `photo_sources.json` 으로 사진을 찾아 교체한다. 허락 메일 양식은 필요할 때 만든다
- 구글이 Veo 생성 실패분(code 13)을 청구하는지 — 청구서로 대조 전까지 장부는 보수적으로(요청 시점) 적는다
