# 미래마켓 개조 기획서

> Claude Code 실행용 마이그레이션 스펙 · 2026-07-26
> 대상: 기존 미래마켓 프로젝트 (쿠팡 어필리에이트 쇼츠 파이프라인)
> 성격: 신규 구축이 아니라 **기존 코드 개조(리팩터링·전환)**

---

## 0. Claude Code 수행 지침 (최우선)
- 이 문서는 **단일 진실 원천(SSOT)** — 기존 코드와 이 문서가 충돌하면 **무조건 이 문서를 따름**
- 코드 수정 전에 **§4 코드베이스 감사부터 수행** — 현재 상태를 실제 코드로 확인한 뒤 개조 계획 수립
- 스펙이 모호하면 임의 구현 금지 → 사용자에게 질문 후 진행
- 개조는 단계별 진행, 각 단계 완료 기준(DoD) 충족 후 다음 단계
- 기존 동작 경로는 새 경로 검증 전까지 유지 (한 번에 갈아엎지 않음)

---

## 1. 개조 목적
- 기존 미래마켓을 아래 파이프라인으로 전환
  - 틱톡 등에서 쇼핑 쇼츠 소재 **자동 소싱** (자동 + 반자동 이중 모드)
  - 운영자가 **구간·줌 수동 편집**
  - **자막·더빙 자동화** (Gemini API 단일 벤더)
  - 다중 플랫폼 **수동 발행** + 쿠팡 파트너스 제휴 링크
- 실행 인프라를 **Cloudflare Workers + Containers + R2** 기준으로 통일
- 최종 산출물: 약 20초 내외 쇼츠

---

## 2. 우선순위 규칙 (충돌 해소 원칙)
- 기존 방식 ≠ 이 문서 → **이 문서 채택**
- 기존 방식 = 이 문서 → 유지
- 기존에만 있고 이 문서에 없는 요소 → 삭제 아님, **유지 후 검토** (§12 유지 항목 우선 확인)
- 판단이 애매하면 삭제하지 말고 질문

---

## 3. 기존 미래마켓 추정 현황 (감사로 확정 필요)
> 아래는 과거 스펙 기준 추정 — 실제 코드가 다르면 실제 코드 기준으로 갱신

- 컨셉: "미래에서 온 화자"가 신문물 소개하는 세계관, 신기한 물건 큐레이션
- 수익: 쿠팡 파트너스 제휴 수수료 (YPP 광고수익 아님)
- 소재 리서치: YouTube Data API v3 기반 (스크래핑 아님)
- 대본: 타 영상 대본 추출이 아니라 **상품 데이터 기반 오리지널 생성**
- 비주얼: **CC0 스톡 또는 자체 생성 에셋** (타 영상 클립 재사용 금지)
- 런타임: **GitHub Actions(ubuntu-latest)** 추정 (아이패드·사내망 제약 대응 목적)
- 준수 가드레일: 공정위 제휴 고지 문구 자동 삽입, 표시광고법 금지 표현 필터, 에셋 라이선스 화이트리스트
- 업로드 모듈에서 고지 문구 누락 시 업로드 중단(assert) 로직

## 4. 선행 작업 — 코드베이스 감사 (Claude Code 첫 단계)
- 프로젝트 전체 구조·모듈·설정(config) 읽기
- 현재 런타임 확인 (GitHub Actions인지 / 이미 Cloudflare인지 / 혼재인지)
- 현재 소재 소싱 방식 확인 (YouTube Data API / 기타)
- 현재 영상 생성 방식 확인 (자체 에셋 / 타 영상 사용 여부)
- 현재 자막·더빙(TTS) 처리 방식·벤더 확인
- 준수 가드레일(고지 문구·라이선스 필터) 구현 위치 확인
- **이 문서와 충돌·차이 나는 지점을 목록으로 산출** (코드 수정 없이 보고만)

## 5. 목표 시스템 구조 (Cloudflare 기준)
- **Cloudflare Workers**: 관리자 페이지 서빙, API 라우팅, 소싱 크론 트리거, 상태 조회
- **Cloudflare Containers**: yt-dlp 다운로드, FFmpeg 합성, Gemini 호출 폴링 등 장시간·고부하 작업
- **R2 스토리지**: 원본·중간 산출물·완성본·메타데이터 저장
- **Gemini API**: STT·번역·TTS 단일 벤더
- **Cron Triggers**: 매일 자동 소싱 스케줄
- 원칙: 다운로드·FFmpeg·폴링은 **반드시 Containers** (Workers 실행 제한 회피)

---

## 6. 소싱 엔진 (자동 + 반자동 이중 모드)

### 6.1 공통
- 쇼핑 관련 쇼츠 소재 수집
- 선택 주제 연관 제품 영상 5~10개 확보
- yt-dlp로 워터마크 없는 원본 다운로드
- 영상별 메타데이터(조회수·URL·태그·수집일·소싱 모드) 저장

### 6.2 자동 모드
- 정해진 시각 크론 실행
- 트렌드·조회수 상위 기준 소재 자동 탐색
- 틱톡 공식 검색 API 부재 → 차단·구조 변경 대비해 소싱 어댑터 분리 설계

### 6.3 반자동 모드
- 운영자가 시드 주입 (해시태그·크리에이터·키워드·특정 URL)
- 주입된 시드 기준으로만 수집
- 자동 모드 불안정 시 폴백 경로로 사용

### 6.4 모드 전환
- 관리자 페이지에서 자동/반자동 선택 가능
- 자동 결과 부족 시 반자동으로 보충

---

## 7. 편집 대시보드 (제작 페이지)
- 아이패드 브라우저 터치 최적화
- 그날 소싱 영상 리스트 뷰 (썸네일·조회수·출처·소싱 모드)
- 영상별 프리뷰 플레이어
- 구간 설정: 시작/끝 타임코드, 복수 구간 선택
- 줌 설정: 구간별 확대 영역·배율·시점
- 클립 순서 드래그 재배치
- 후킹 클립 지정
- "자막·더빙 실행" 버튼
- 처리 진행 상태 표시
- 완성본 프리뷰 + 다운로드
- 원칙: 편집 구간·줌은 운영자 수동, 나머지는 버튼 한 번 자동

---

## 8. 자막·더빙 파이프라인 (Gemini 단일)
1. 합성 영상에서 오디오 추출
2. Gemini STT로 원문 추출 (타임스탬프 포함)
3. Gemini 번역으로 한국어 변환
4. 자막 파일 생성 (SRT/ASS) — 카라오케 자막 스타일 옵션
5. Gemini TTS로 한국어 더빙 생성
6. FFmpeg로 자막 번인 + 더빙 오디오 믹싱
- 벤더 정책: **Gemini API 단일 확정** (STT·번역·TTS)
- TTS 어댑터는 인터페이스로 추상화 (추후 벤더 교체 여지만 확보, 기본은 Gemini)

---

## 9. 저장·배포 구조
- R2 버킷: `/raw`(원본) · `/clips`(중간) · `/output`(완성) · `/meta`(메타·자막·설정)
- 완성본은 발행 대기 큐 적재
- 발행은 **수동** (플랫폼별 업로드 + 제휴 링크 삽입)
- 발행 채널·발행 여부 상태 기록
- 유지: 공정위 제휴 고지 문구 자동 삽입 로직 (§12)

---

## 10. 하루 운영 흐름
1. 크론 실행 → 소싱(자동/반자동) → R2 재료 적재 + DB 등록
2. 운영자 관리자 페이지 접속
3. 그날 발행 건수 결정 (1~2건 등 유동)
4. 영상별 구간·줌·순서 설정
5. "자막·더빙 실행" → 자동 합성
6. 완성본 검수·다운로드
7. 유튜브·인스타·네이버 등 수동 발행 (고지 문구·제휴 링크 포함)

## 12. 유지 항목 (기존에서 반드시 살릴 것)
- 쿠팡 파트너스 제휴 수익 모델
- **공정위 제휴 고지 문구 자동 삽입** (표시·광고의 공정화에 관한 법률 근거) + 누락 시 중단 로직

- 반복성 회피 원칙 (영상마다 고유 소재·고유 산출물)

## 13. 충돌·변경 항목 (⚠️ 개조 전 반드시 확인)

### 13.1 런타임 전환 (대형 변경)
- 기존 추정: GitHub Actions(ubuntu)
- 개조 후: Cloudflare Workers + Containers + R2
- 영향: 실행 환경·배포·에셋 저장 구조 전면 변경 → **소규모 수정 아님, 단계적 이전 필요**
- 감사에서 이미 Cloudflare면 이 항목 스킵

### 13.2 영상 소재 재사용 방식 (저작권 충돌 — 핵심)
- 기존 미래마켓은 **저작권 리스크 때문에** "타 영상 클립 재사용 금지 + CC0/자체 생성" 원칙으로 설계됨
- 이번 개조의 "타 쇼핑 영상 5~10개 짜깁기" 방식은 **그 결정을 뒤집는 방향** → 기존에 회피했던 저작권·플랫폼 정책 리스크 재유입
- 우선순위 규칙상 이 문서가 우선이나, 이는 **의식적 결정이 필요한 사안** — 다음 중 택일 권장
  - (A) 소싱 영상 그대로 짜깁기 (리스크 최고, ToS·저작권 노출)
  - (B) 소싱 영상은 **레퍼런스로만** 쓰고 실제 화면은 제조사 제공 소재·쿠팡 상품 이미지·CC0 b-roll로 재구성 (기존 원칙과 정합)
  - (C) 소싱 영상을 상당히 변형·재가공해 사용 (부분 완화, 여전히 회색지대)
- **소싱 모듈 코드는 공통이므로 먼저 구현하되, "완성본에 원본 영상을 그대로 쓰는지" 정책은 감사 후 사용자가 최종 결정**

### 13.3 소재 리서치 소스 전환
- 기존: YouTube Data API 리서치
- 개조 후: 틱톡 등 쇼핑 영상 소싱(자동/반자동) + yt-dlp
- YouTube Data API 리서치 로직은 삭제 아님, **소재 발굴 보조로 유지 검토**

## 14. 개조 진행 단계 (마이그레이션 Phase)
1. **감사** — §4 수행, 충돌·차이 목록 + 개조 계획 산출 (코드 수정 없음)
2. **인프라 이전** — Cloudflare Workers + Containers + R2 스캐폴딩, 배포 파이프라인 (기존 경로 병행 유지)
3. **소싱 엔진** — yt-dlp 다운로드 + 자동/반자동 이중 모드 + 메타데이터 저장
4. **데이터·저장 구조** — R2 버킷 + DB 스키마(§11)
5. **편집 대시보드** — 리스트 → 프리뷰 → 구간·줌·순서 설정
6. **자막·더빙** — Gemini STT·번역·TTS + FFmpeg 합성
7. **완성본·발행 큐** — 프리뷰 + 고지 문구·제휴 링크 유지
8. **크론 자동 소싱 연결**
9. **구 경로 제거 + 통합 테스트**
